# Выборочный DNS over TLS в ByeByeDPI × TG

Дата: 22 октября 2026 г.

## Цель и критерии успеха

Пользователь сейчас запускает ByeByeDPI × TG вместе с RethinkDNS, чтобы назначить DNS over TLS (DoT) на `geohide.ru` нескольким приложениям. Нужен один VPN: ByeByeDPI продолжает обрабатывать трафик как прежде, а DNS-запросы приложений из отдельного списка уходят на `geohide.ru` по TLS. DNS остальных приложений, включённых в VPN, сохраняет существующее поведение. Функция рассчитана на Android 17 пользователя; приложение поддерживает также более ранние версии Android.

Успех проверяется по установленным приложениям: выбранное приложение получает ответы от `geohide.ru` через TLS, приложение вне DNS-списка использует прежний DNS, а обычный трафик обоих приложений по-прежнему проходит через ByeDPI. Остановка DoT-сервера и невозможность установить TLS должны приводить к видимой ошибке, без незаметного перехода выбранного приложения на незашифрованный DNS.

## Текущее устройство

`ByeDpiVpnService` создаёт один VPN с общим DNS-адресом из `Configuration.dns`. `NativeSession` передаёт TUN-дескриптор в встроенный `hev-socks5-tunnel`, который пересылает пакеты через локальный SOCKS5-сервер ByeDPI. Существующий фильтр приложений выбирает, чей **весь трафик** входит в VPN. Он не задаёт DNS по приложениям. При активном системном Private DNS приложение отдаёт настройку DNS системе.

## Выбранный подход

Добавить отдельный список приложений для DoT, не связывая его с текущим списком VPN. Внутри существующего TUN-потока направлять обычные DNS-запросы к локальному обработчику, определять UID исходного приложения по сетевому соединению через доступный Android API и выбирать маршрут по UID. Для выбранных UID обработчик отправляет запрос на `geohide.ru:853` с проверкой сертификата и имени узла; для остальных сохраняет прежний путь. Ответ возвращается в исходный DNS-поток. Сокеты обработчика защищаются от повторного попадания в VPN через `VpnService.protect` и привязываются к подходящей внешней сети.

`VpnService.Builder.addDnsServer` сам по себе не решает задачу: этот адрес общий для VPN. Отдельный VPN только для DNS невозможен, поскольку Android разрешает один активный VPN для пользователя. Вариант «DoT для всего VPN и whitelist приложений» меняет обработку остальных приложений, поэтому не соответствует цели.

## Проверка осуществимости перед основной реализацией

Первый этап реализации — инструментированная проверка на Android 17: для запросов стандартного системного резолвера и прямых UDP/TCP запросов на порт 53 определить, возвращает ли `ConnectivityManager.getConnectionOwnerUid` UID исходного приложения. Проверить как минимум два приложения с различными UID. Если системный резолвер даёт только UID системного процесса или `INVALID_UID`, нельзя считать выборочный DNS реализуемым этим способом. В таком случае остановить реализацию, записать измеренные результаты и согласовать другой подход; не выпускать настройку, которая выборочно работает лишь на некоторых приложениях без явного ограничения.

Возможная следующая архитектура при провале проверки — собственное сопоставление запросов с приложениями на другом уровне, но она требует отдельного проекта. Эта спецификация её не утверждает.

## Поведение и границы

- Настройка доступна только в режиме VPN. По умолчанию выключена, список пуст, существующие установки сохраняют прежнее поведение.
- DNS-список хранится отдельно от `selected_apps`; экспорт, импорт и сброс настроек сохраняют или удаляют его вместе с настройками приложения. Название и состояние функции видны в настройках.
- Приложение из DNS-списка должно быть включено в VPN. При конфликте с VPN whitelist/blacklist интерфейс показывает причину и не обещает применение DoT. Самовольное изменение VPN-списка не производится.
- Пользователь может включить DoT на `geohide.ru` и выбрать приложения. Адрес сервера в этой задаче фиксирован; настройка произвольного DoT-сервера не входит в объём.
- Системный Private DNS или DNS внутри HTTPS/QUIC приложения может обходить DNS-пакеты порта 53. Интерфейс объясняет это ограничение и не заявляет, что весь DNS приложения всегда контролируется.
- Поддержать UDP и TCP DNS на порту 53, а также IPv4/IPv6 в рамках включённого для VPN IPv6. Не перехватывать и не подменять DoH/DoQ приложения.
- Для DNS-запроса с неизвестным UID при включённом выборе DoT не предполагать, что он относится к выбранному приложению. Событие диагностируется; если это типичный путь системного резолвера, проверка осуществимости останавливает реализацию до выпуска.
- Для запросов выбранного приложения ошибка TLS, таймаут или неверный сертификат возвращаются как ошибка DNS и отображаются в состоянии/диагностике; перехода на обычный DNS нет.
- Разрешение адреса самого `geohide.ru` выполняется через внешнюю сеть. Это служебный bootstrap-запрос; его способ и возможная видимость оператору должны быть описаны в интерфейсе или документации. DNS-запросы выбранных приложений в bootstrap не передаются.

## Изменения компонентов

1. Настройки: переключатель DoT, отдельный экран выбора приложений на основе существующего `AppSelectionFragment`/адаптера с параметризованным ключом предпочтения, краткое состояние и предупреждение о конфликте с VPN-фильтром.
2. Конфигурация и IPC: передать включение DoT и список пакетов от настроек в `NativeEngine`, `Configuration`, `EngineProtocol`, `NativeSession` и VPN-сервис. Преобразовать пакеты в UID перед запуском туннеля; обработать удалённые приложения.
3. Туннель: минимальный перехват DNS-пакетов до передачи в SOCKS5, сохранение адресов/портов/идентификаторов и возврат корректных ответов. Для прочего трафика оставить текущую пересылку.
4. DoT-клиент: защищённое TLS-соединение с проверкой имени `geohide.ru`, DNS length-prefix framing по RFC 7858, ограничения размеров, таймауты, управление жизненным циклом и отказ без plaintext fallback.
5. Диагностика: показать фактическое состояние, ошибки соединения и случаи, когда запрос нельзя связать с приложением. Не логировать содержимое DNS-запросов по умолчанию.

## Проверка

- До редактирования основного потока: подтвердить UID для двух приложений и двух видов DNS-запросов на Android 17.
- Модульные тесты для выбора маршрута по UID, конфликтов VPN-списка, DNS framing, таймаутов и обработки ошибок.
- Интеграционная проверка на устройстве: выбранное и невыбранное приложения, UDP/TCP, IPv4/IPv6 при включении, неверный сертификат, недоступный сервер, активный системный Private DNS, включение/выключение и перезапуск VPN.
- Собрать debug APK и проверить, что обычный VPN, прокси-режим и импорт/экспорт настроек работают после изменений.

## Не входит в задачу

Изменение системного Private DNS, поддержка произвольных DoT-провайдеров, принудительный перехват DoH/DoQ приложений и запуск второго VPN.
